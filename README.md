# SchoolDay

SchoolDay is a student-focused daily command center that answers one question: **What matters for school right now?** It brings schedule timing, assignment urgency, official grade movement, and recent gradebook activity into one calm browser start page.

The dashboard includes live Bell-Logic, Canvas, and StudentVUE integrations. It selects each live provider when its server-only configuration is present and falls back per provider when a service is unavailable.

> [!IMPORTANT]
> SchoolDay is currently a pre-1.0, single-user self-hosted application. It does not include user authentication, and its dashboard and API responses can contain private student data. Keep the published port bound to loopback, or place the app behind an authenticated reverse proxy or access gateway. Do not expose the container directly to the public internet.

## Current implementation

- Responsive SvelteKit dashboard with current and next periods, a live countdown, and period progress.
- Deterministic “What Matters” ranking with configurable weights and human-readable reasons.
- Current grades with movement from the prior StudentVUE fixture snapshot.
- Grade-change feed generated by the actual before/after diff and persistence pipeline.
- Daily schedule state for completed, current, and upcoming periods.
- Seven-day Canvas assignment view with submission state, points, due time, and fixture deep links.
- Validated mock Canvas, StudentVUE, and Bell-Logic providers behind production-shaped interfaces.
- A real server-side Bell-Logic provider with response validation, timeout handling, request deduplication, and short-lived caching.
- A real server-side Canvas REST provider with bearer authentication, opaque-link pagination, bounded retries, course/assignment concurrency, and seven-day calendar loading.
- A real server-side StudentVUE web provider with authenticated session handling, course and grade parsing, gradebook-detail loading, and normalized assignments.
- Normalized SchoolDay models, course matching, grade sync, storage-independent repository contracts, and restart-safe SQLite grade history.
- Lightweight on-demand sync with a 15-minute Canvas freshness window, durable Canvas assignment snapshots, and per-provider sync auditing.
- A 30-minute StudentVUE freshness window with last-known-good grade fallback instead of demo data during outages.
- Durable automatic Canvas, StudentVUE, and Bell-Logic course mappings.
- Configurable school-service quick links and minimal installable start-page metadata.
- Conservative Canvas-to-StudentVUE assignment reconciliation with complete, awaiting-grade, missing, excused, and possible-mismatch states.
- Dashboard polish with useful empty states, degraded/stale source notices, and interactive assignment-window filters.
- Portable SQL migration for courses, mappings, assignments, submissions, grade history, events, sync audits, and settings.
- Unit coverage for priority ranking, grade changes and idempotency, schedule state, fixture variants, and course matching.

The default dashboard is anchored to a realistic **Monday, August 10, 2026 A-day at 9:10 AM**. The countdown advances live in the browser from the fixture period’s start/end times. Anchoring the preview keeps the central in-session experience visible regardless of when development occurs.

## Stack

- Svelte 5 and SvelteKit
- strict TypeScript
- Vite and Vitest
- Node.js server runtime packaged as a Docker image
- hardened Docker Compose deployment bound to the host loopback interface
- Storage-independent repository contracts and a portable SQL schema foundation
- Zod validation at fixture/provider boundaries
- plain responsive CSS (no client UI framework)

## Run locally

Requirements: Node.js 24+ and pnpm 11+.

```bash
pnpm install
pnpm dev
```

Open the local URL printed by Vite, normally `http://localhost:5173`.

No environment variables or database are required for the fixture dashboard. To exercise live integrations, copy `.env.example` to `.env`, fill in the server-only values, and start Vite with that file loaded into its Node process:

```bash
pnpm dev:integrations
```

Provider variables are documented in `.env.example`. All `.env` variants except `.env.example` are Git-ignored.

## Run with Docker

The production deployment target is a self-hosted Node.js container. The app listens on port 3000 inside the container and Compose publishes it only on the Docker host's loopback interface by default.

### Deploy the published image

Release images are published to the GitHub Container Registry, so a server only needs `compose.yaml` and a private `.env` file—not a clone of this repository. Download those two files, review the configuration, and start the image:

```bash
mkdir schoolday && cd schoolday
curl -fsSLO https://raw.githubusercontent.com/RRyankees08/schoolday/main/compose.yaml
curl -fsSLo .env https://raw.githubusercontent.com/RRyankees08/schoolday/main/.env.example
chmod 600 .env
docker compose pull schoolday
docker compose up -d schoolday
curl http://127.0.0.1:3000/api/health
```

Edit `.env` before startup and add only the live-provider credentials you need. `latest` is published for a versioned release; for a repeatable deployment, set `SCHOOLDAY_IMAGE` to a version tag such as `ghcr.io/rryankees08/schoolday:0.1.0`. Before the first release, the `edge` tag tracks the default branch. The repository owner must make the GHCR package public after its first publication; until then, Docker must authenticate with a GitHub token that has `read:packages`.

Update the pinned tag in `.env`, then run `docker compose pull schoolday && docker compose up -d schoolday`. The database survives container replacement because it is stored in the `schoolday-data` named volume.

### Build from source with Compose

```bash
cp .env.example .env
docker compose up -d --build schoolday
curl http://127.0.0.1:3000/api/health
```

Set `SCHOOLDAY_PORT` if port 3000 is already occupied. Set `ORIGIN` to the browser-facing URL (for example, `https://schoolday.example.com`) when exposing the app through an authenticated reverse proxy or tunnel. Keep `.env` private because it contains Canvas and StudentVUE credentials.

Compose stores live StudentVUE grade snapshots and detected changes in the `schoolday-data` named volume at `/data/schoolday.sqlite`. The schema is migrated automatically during application startup. Fixture-only runs remain in memory so demonstration grades can never be compared with a later live StudentVUE sync.

To make a consistent database backup, briefly stop the app, copy the database out, and restart it:

```bash
docker compose stop schoolday
docker compose cp schoolday:/data/schoolday.sqlite ./schoolday.sqlite.backup
docker compose start schoolday
```

Keep this backup private because it contains grade history. Removing the Compose stack does not remove the named volume unless `docker compose down --volumes` is used.

## Configuration

SchoolDay runs entirely with fixtures when live provider credentials are absent. Variables are server-only unless noted otherwise.

| Variable                                                                | Required                       | Purpose                                                                              |
| ----------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------ |
| `SCHOOLDAY_IMAGE`                                                       | No                             | Container image used by Compose; defaults to `ghcr.io/rryankees08/schoolday:latest`. |
| `ORIGIN`                                                                | Production                     | Browser-facing origin used by the SvelteKit Node server.                             |
| `SCHOOLDAY_PORT`                                                        | No                             | Host port published by Docker Compose; defaults to `3000`.                           |
| `SCHOOLDAY_DISPLAY_NAME`                                                | No                             | Name used in the greeting; defaults to `Student`.                                    |
| `SCHOOLDAY_DB_PATH`                                                     | Live StudentVUE outside Docker | SQLite database path. Docker configures `/data/schoolday.sqlite` automatically.      |
| `CANVAS_BASE_URL` and `CANVAS_TOKEN`                                    | Together                       | Canvas REST API origin and bearer token.                                             |
| `CANVAS_WEB_URL`                                                        | No                             | Browser-facing Canvas destination when different from the API origin.                |
| `STUDENTVUE_BASE_URL`, `STUDENTVUE_USERNAME`, and `STUDENTVUE_PASSWORD` | Together                       | StudentVUE portal origin and login credentials.                                      |
| `STUDENTVUE_WEB_URL`                                                    | No                             | Browser-facing StudentVUE destination when different from the portal origin.         |
| `BELLLOGIC_API_URL` and `BELLLOGIC_REQUEST_ORIGIN`                      | Together                       | Bell-Logic endpoint and its allowlisted request origin. Defaults are provided.       |
| `BELLLOGIC_WEB_URL`                                                     | No                             | Browser-facing Bell-Logic destination.                                               |

See [`.env.example`](./.env.example) for a copyable template. An incomplete provider credential set is treated as a configuration error for that provider and SchoolDay falls back to its fixture data.

## Fixture providers

Raw fixture payloads live under `fixtures/`:

```text
fixtures/
  canvas/       courses, assignments, submissions, calendar events
  studentvue/   before and after gradebook snapshots
  belllogic/    regular A, regular B, and early-release schedules
```

Each mock provider implements the same interface intended for the future real provider. Raw payloads are runtime-validated and normalized inside provider-specific modules. The dashboard never imports provider response shapes.

`createScheduleProvider()` continues to return `MockBellLogicProvider` by default, keeping tests deterministic. Server routes select the real provider when the required environment configuration is available:

```ts
const schedule = createScheduleProvider({
  mode: 'belllogic',
  apiUrl: env.BELLLOGIC_API_URL,
  origin: env.BELLLOGIC_REQUEST_ORIGIN
});
```

SchoolDay reads Bell-Logic from the public `https://api.bell-logic.us` host and uses `https://bell-logic.us` as the approved public website origin. Both defaults are declared in `.env.example` and `compose.yaml` and can be overridden by server-only environment variables. The public Siri route is not used because it does not contain the full daily period list required by `ScheduleProvider`.

Canvas follows the same explicit composition pattern. `createCanvasProvider()` returns fixtures by default, while server routes select the REST implementation with server-only credentials:

```ts
const canvas = createCanvasProvider({
  mode: 'canvas',
  baseUrl: env.CANVAS_BASE_URL,
  token: env.CANVAS_TOKEN
});
```

The provider requests active student courses, follows every opaque Canvas pagination link, includes the current user's submission with each assignment, and batches course calendar contexts in groups of ten. The bearer token is sent only in the `Authorization` header and pagination is restricted to the configured Canvas API origin.

Without StudentVUE configuration, the fixture demo intentionally exercises:

- one course-grade increase and one decrease;
- a first assignment grade;
- a corrected score;
- missing added and missing resolved;
- an unchanged assignment whose sync metadata changes but emits no event.

On initialization, the server syncs the normalized before snapshot and then the after snapshot through the grade-change engine. Generated events are appended to the repository and the dashboard reads the event feed back from that repository. Reprocessing the after snapshot is idempotent.

## Architecture

```text
raw provider fixture
  → provider schema validation
  → provider-specific normalization
  → course identity matching
  → priority / schedule / grade-sync domain services
  → repository contracts (in-memory fixtures, durable SQLite for live grade history)
  → dashboard application service and /api/dashboard
  → presentation-only Svelte components
```

Important boundaries:

- `src/lib/models/` — normalized SchoolDay domain models.
- `src/lib/server/providers/` — provider contracts, validation, normalization, and mocks.
- `src/lib/server/matching/` — provider-local to SchoolDay identity matching.
- `src/lib/server/priority/` — deterministic ranking weights and explanations.
- `src/lib/server/grade-changes/` — meaningful snapshot comparison only.
- `src/lib/server/sync/` — compare, persist events, then persist incoming snapshot.
- `src/lib/server/db/` — repository contracts plus in-memory and SQLite implementations.
- `src/lib/server/dashboard/` — aggregated dashboard orchestration.
- `src/lib/components/` — presentation components consuming only normalized dashboard data.
- `migrations/0001_initial.sql` — initial portable SQL schema.

Fixture mode uses `InMemoryGradeRepository` and stays zero-setup. When all StudentVUE credentials and `SCHOOLDAY_DB_PATH` are configured, the runtime selects `SQLiteGradeRepository`. Docker configures this automatically and mounts its database in a persistent named volume. SQLite runs with foreign keys, a five-second busy timeout, and WAL journaling; snapshot writes and event inserts are transactional and event IDs remain idempotent across restarts.

## What remains

Real integration should follow the specification’s required order:

1. **Bell-Logic:** authorize SchoolDay's production origin and verify live special-day timing. Runtime selection and degraded fallback are implemented.
2. **Canvas:** live normalized results are stored in SQLite when configured and reused for 15 minutes or whenever Canvas is temporarily unavailable.
3. **StudentVUE:** web authentication, normalized courses and grades, assignment-detail loading, runtime selection, durable grade history, cached refresh cadence, and last-known-good fallback are implemented.

SchoolDay intentionally refreshes on page load when stale or from the small **Sync now** control; it does not require a scheduler or background service. Automatic course mappings are retained locally, and quick links are configured through environment values. The daily briefing intentionally remains a single page rather than growing separate assignments, grades, schedule, or settings sections. Authentication, extensions, AI features, and hypothetical-grade tools are outside this scope.

### StudentVUE integration

SchoolDay uses the same StudentVUE web portal as a student browser session. It does not use the deprecated SOAP mobile API or attempt to bypass StudentVUE (New) device attestation. Add the three `STUDENTVUE_*` values from `.env.example` to `.env`, then run the privacy-safe connection check:

```bash
pnpm studentvue:poc
```

The read-only probe reports only pass/fail results and record counts. It never prints credentials, course names, grades, assignment names, or authenticated response data. Zero grades or assignments is valid when the current grading period is not populated.

Start the dashboard with all configured providers:

```bash
pnpm dev:integrations
```

The header should include `StudentVUE live`. If login or parsing fails, SchoolDay marks StudentVUE degraded and keeps the rest of the dashboard available.

For a self-hosted deployment, store credentials in the Docker host's private `.env` file (mode `0600` is recommended) or use your container platform's secrets feature. Credentials are read only by server code and are never sent to the browser.
